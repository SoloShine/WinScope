# WinScope 剩余功能实现计划总结

**日期**: 2026-05-02

## 概述

本文档总结了 WinScope 项目的三个剩余功能的实现计划。每个功能都是独立的子系统，可以按任意顺序实现。

## 功能列表

### 1. 历史缩略图时间线

**目标**: 允许用户回溯查看窗口的历史状态变化

**计划文档**: `docs/superpowers/plans/2026-05-02-history-timeline.md`

**设计文档**: `docs/superpowers/specs/2026-05-02-history-timeline-design.md`

**主要任务**:
- 添加历史相关类型定义
- 创建 useHistory hook
- 集成历史记录到 useCapture hook
- 创建 HistoryTimeline 组件
- 创建 HistoryPreview 组件
- 更新 WindowCard 组件添加历史按钮
- 更新 WindowGrid 组件传递历史回调
- 更新 App.tsx 集成历史预览
- 添加国际化翻译
- 端到端测试

**依赖**: 无（依赖现有的 capture 系统）

**复杂度**: 中等

**预计工作量**: 2-3 天

## 实现顺序建议

### 方案 A: 按复杂度递增

1. **系统托盘** (低复杂度) - 1-2 天
2. **历史缩略图时间线** (中等复杂度) - 2-3 天
3. **多显示器过滤** (中等复杂度) - 2-3 天

**优点**: 从简单开始，逐步建立信心
**总时间**: 5-8 天

### 方案 B: 按用户价值

1. **系统托盘** - 最常用功能，提升用户体验
2. **多显示器过滤** - 多显示器用户必需
3. **历史缩略图时间线** - 高级功能，使用频率较低

**优点**: 优先实现最有价值的功能
**总时间**: 5-8 天

### 方案 C: 并行实现

三个功能独立，可以并行开发：

- 开发者 A: 系统托盘
- 开发者 B: 历史缩略图时间线
- 开发者 C: 多显示器过滤

**优点**: 最快完成
**总时间**: 2-3 天（如果资源充足）

## 技术风险

### 1. 历史缩略图时间线

**风险**: 内存占用过高
**缓解**: 限制最大条目数（20 张），使用压缩缩略图

### 2. 系统托盘

**风险**: Tauri 托盘插件兼容性问题
**缓解**: 使用官方插件，参考官方文档

### 3. 多显示器过滤

**风险**: Win32 API 调用复杂性
**缓解**: 参考现有 windows crate 用法，逐步测试
